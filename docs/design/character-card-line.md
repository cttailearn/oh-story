# 角色卡与角色线：设定模块的双份管理（v0.1）

> 配套 [`character-line-management.md`](character-line-management.md)（理论：三层结构 + 方案 A/D）、[`webui-frontend.md`](webui-frontend.md) §3.1、[`data-model.md`](data-model.md)、[`process-definition.md`](process-definition.md)。
> 本文把「**角色卡**（不变契约）」与「**角色线**（变化演进）」**拆成两份文件独立管理**，并给出：边界、文件契约、前端管理模型（双视图 + 看板）、AI 注入、门禁审计。

---

## 0. 一句话
> **角色卡回答"他是谁"，角色线回答"他如何变"。** 卡是**契约**（改卡要谨慎，红线 grep 死保）；线是**演进**（每章可推进，阶段状态机 + 验收 + 审计）。两者分开存、分开管理、由一致性门禁交叉校验，追踪状态仍是"当前事实"的唯一权威。

---

## 1. 为什么拆两份（边界表）
| 维度 | 角色卡（`设定/角色/{名}.md`） | 角色线（`设定/角色线/{名}.md`） |
|---|---|---|
| 回答 | 是谁（本质/身份/能力/口癖/红线） | 怎么变（弧线/阶段/验收/证据/审计） |
| 变更频率 | 低频（设定期 + 重大设定修订） | 高频（每卷/每章的推进） |
| 权属 | 写作红线、语言风格档案（对话音色唯一权威） | 阶段状态机、渐变证据、卷末审计 |
| 一致性机制 | consistency-checker 逐条 grep 红线 | **role-line gate**（阶段 vs 进度 / 验收证据） |
| 前端形态 | 角色卡网格（卡片式） | 角色线看板（泳道 + 阶段表） |
| AI 介入 | 设定期：architect 起草，designer 补风格 | 规划：architect 出弧线；写作：writer 按 active 阶段注入 |

> 边界铁律：**跨时期永久形态事实（能力上限、外貌、说话方式）留卡**；**随情节变化的状态、目标、关系距离进线或追踪快照**，禁止两处定义同一事实造成漂移（由 role-line gate 兜底）。

## 2. 文件契约（两份 schema）

### 2.1 角色卡 `设定/角色/{角色名}.md`
```markdown
# 角色卡：沈栀（女主）
## 基础信息
- 身份：…（括号前结论供 checker 机械比对）
## 形象与能力
- 外貌：…（跨时期永久事实）
- 能力表（分时期）：阶段A(能力X) / 阶段B(能力Y)；**能力上限**=…（永久形态事实）
## 说话方式（语言风格档案·唯一权威）
- 称呼/口头禅/句式/不出口的心里话…
## 核心锚点（供角色线起点）
- 信念：… ｜ 欲望（Want）：… ｜ 恐惧/创伤（Ghost）：…
## 写作红线
- 绝不做：…（consistency-checker 逐条 grep，blocking）
## 本书专属
- 与伏笔：F0xx 绑定；特殊规则…
```
- 元数据（可选 frontmatter）：`name / aliases / role_line_file:`（默认同名线文件，自动关联）。

### 2.2 角色线 `设定/角色线/{角色名}.md`
```markdown
# 角色线：沈栀（自我价值觉醒）
## 弧线定义
- 起点（读卡）：戒备→不相信自己 | 终点：敢为自己下决心
- 主题：信念「被需要才算有用」→真相「价值不由他人定义」
- Want / Need / Ghost：…
## 阶段状态机
### 阶段 1：戒备→微暖（第1-8章）[状态: done]
- 三层目标：内在=开始接纳善意；外在=无；关系=与主角破冰
- 验收：读者能看到「沈栀没有拒绝主角的顺手帮忙」（✓第6章）
- 渐变证据：第3章拒绝帮忙 / 第6章默许 / …
### 阶段 2：依赖→独立（第9-30章）[状态: active]
- 三层目标：… | 验收：… | 渐变证据：…
### 阶段 3：…（第X卷）[状态: planned]
## 与其他线交织点
- 与男主线：情感升温的节奏耦合点（第12章）
## 进度指针
- 当前阶段：阶段 2（active）｜ 最近确认到：第 18 章
## 审计结果（卷末由 role-line gate 回填）
- v1：阶段1 验收通过（证据3条）；阶段2 进度正常（8/21 章产出证据 4 条）
```

### 2.3 事实权威三角
```
设定/角色线/{名}.md  ← 规划层（arc/阶段/验收）        [可被 AI 建议、人工确认推进]
设定/角色/{名}.md    ← 契约层（不变事实/红线）          [修改低频、需谨慎]
追踪/_tracking-state.json + 追踪/角色状态/{名}.md ← 事实层（当前 state/goal/open_threads）[唯一写路径 tracking-commit]
         └── role-line gate：三者交叉校验（阶段 active ⇔ 最近章节 ⇔ 追踪 state）
```
- **写权限**：卡/线经 `PUT /files`（mtime 乐观锁）；追踪仅 `tracking-commit`。角色线阶段推进**不写追踪**，仅更新线文件 + `audit`。

## 3. 前端管理模型（设定模块）

### 3.1 双区布局
```
设定 → 角色 区：  [角色卡] [角色线]   （两个页签并排，左卡右线可联动）
 角色卡 页签：    角色卡网格（头像/姓名/身份/红线计数/「▶ 看角色线」）
 角色线 页签：    角色线看板（见 3.2）
```

### 3.2 角色线看板（新组件 `CharacterLineBoard`）
```
┌ 角色线看板 ─────────────────────────────────────────────┐
│ 泳道: 沈栀（女主·自我价值觉醒）                          │
│   阶段条: [done 阶段1 1-8][active 阶段2 9-30][planned 阶段3 …] │
│   进度指针 ▼ 第18章 · 验收: 阶段2 目标「独立」部分达成(2/5 ✓)     │
│   审计: 阶段1 通过 ✓ · 阶段2 进度正常(证据4条)                 │
│   [展开阶段表] [AI 提议下阶段] [推进到阶段3]                    │
│ ─────────────────────────────────────────────────────── │
│ 泳道: 江晨（身份逆袭·军宣顶流）   ……                       │
└──────────────────────────────────────────────────────────┘
```
- **阶段表**（展开）：每行=阶段，列=章范围/状态(planned·active·done 徽章)/三层目标/验收打勾/渐变证据数/备注；状态在行内切换（需确认弹层，写 `audit`）。
- **审计徽章**：role-line gate 结果（阶段与进度一致=青黛；验收缺证据=鎏金警示；与追踪冲突=朱 blocking）。

### 3.3 新建角色向导
```
[新建角色] → ①填卡（身份/外貌/能力/说话方式/红线，必填≥4）
          → ②弧线骨架（可选/architect 起草）：起点状态+方向(正弧/平弧/负弧)+终点
          → 建两份文件（卡 + 线：阶段0=planned）→ 卡片入网格 + 泳道入看板
```
- 向导里"仅建卡不留线"允许（配角红线级），但主角建议必须配线（`characters` gate 检查主角有线）。

### 3.4 联动与权限
- 卡片上的「▶ 看角色线」→ 切到线页签并定位该泳道（跨页签 trace）。
- 卡的红线不可被 AI 编辑直接改（AI 只可"提议"，人工采纳）；线的阶段推进也必须人工确认（每步确认原则）。
- 重新生成卡/线都经「AI 编辑」（ai-edit），产物落 Revision，人工采纳后生效。

## 4. AI 与流程注入
- **弧线规划**：`characters` 阶段由 architect 产卡 + 线（方案A 阶段状态机模板）；`AI 提议下阶段`（architect）在困境/卷末触发，产物为"阶段 N 的目标/验收/渐变轨迹"草案 → 人工确认 → 落线文件。
- **写章注入**：`context-chapter` glue 新增 **角色线块**：取相关角色 `active 阶段 + 验收 + 渐变证据末条 + 进度指针`（读线文件 + 追踪快照，token 控制 ≤~400/角色、仅涉场角色）。使命写明：本章是否兑现某验收、不跳阶段、不破坏渐变节奏。
- **去AI味/审查**：`review`/`deslop` 上下文同样可带线摘要，保证改写不越阶段。

## 5. 门禁与审计（新增 `role-line` gate）
| 检查 | 阻断性 | 判定 |
|---|---|---|
| 阶段链合法 | blocking | planned→active→done 有序；active 至多 1 个 |
| 进度指针不越界 | blocking | `last_committed_chapter` 落在 active 阶段章范围内 / 或明确延期备注 |
| 验收证据非空 | warning | active/done 阶段至少 1 条验收证据（done 必须全打钩） |
| 卡线一致性 | blocking | 线内"起点/终点"与卡"核心锚点"命名一致；能力上限未在线上重复定义 |
| 追踪一致性 | warning | 线 active 阶段目标 与 `_tracking-state.json characters.*.state/goal` 大方向不冲突 |
- 检出入列 `gate_runs`；卷末审计结果回填线文件「审计结果」节（方案 D 写后记账）。

## 6. 组件 / API 增补
| 组件 | 说明 |
|---|---|
| `CharacterCardGrid`（已有） | 卡网格，加"红线计数""▶ 看角色线" |
| `CharacterLineBoard`（新） | 角色线看板（泳道 + 阶段条 + 进度指针 + 审计徽章） |
| `RoleStageTable`（新） | 阶段表（状态切换/验收打勾/证据追加） |
| `ArcProposalDrawer`（新） | AI 提议下阶段草案（diff：目标/验收/渐变轨迹）→ 采纳 |
| `AuditBadge`（新） | 审计结果徽章（青黛/鎏金/朱） |

API：
```
GET  /books/:id/characters                  # 卡列表（含红线/角色线关联）
GET  /books/:id/characters/:name/arc        # 线：阶段/进度指针/审计
PUT  /books/:id/characters/:name/arc        # 推进阶段/改验收（写线文件 + audit）
POST /books/:id/characters/:name/arc/propose# architect 提议下阶段（ai-edit 语义）
```
