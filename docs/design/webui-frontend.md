# oh-story WebUI 前端设计（v0.1）

> 配套主方案 [`docs/design/standalone-webui.md`](standalone-webui.md)（技术栈 TS + React + `pi-ai` / `pi-agent-core`）。
> 本文只讲**界面**：信息架构、页面线框、交互流程、组件清单、设计系统。实现细节（路由/状态库）见 §8。

## 1. 设计方向：「书稿编辑部」（Editorial Atelier）

> **一句话记忆点**：像一位资深编辑坐在书桌前批稿——暖纸底色、墨字排印、朱笔批注、章回即书页。它不是"管理后台"，是一座**私人编辑部**。

### 1.1 概念与气质
- 灵感：宣纸/稿纸、线装书、编辑红笔批注、章回体排版。
- 三层空间隐喻：
  1. **书房（项目层）** = 书架，一"本"书一个项目，封面色块 + 书名题签；
  2. **手稿（内容层）** = 某一本随开随写的工作页：设定如"人物谱/舆图"，大纲如"回目表"，正文如"书页"，状态如"批阅栏"；
  3. **批注（协作层）** = 门禁报告、AI 改写 diff、审查意见，全部呈现为"朱批/浮签"，而非普通 error toast。
- 动效气质：翻页/揭启的轻缓过渡，印章盖下的确认反馈，浮签滑入；克制、有仪式感，不炫技。

### 1.2 设计令牌（Design Tokens）
```css
/* 主题一：日间「晴窗纸」 */
--paper:      #F6F1E6;   /* 宣纸暖白 */
--paper-2:    #EFE8D8;   /* 稿纸网格底 */
--ink:        #23201A;   /* 浓墨 */
--ink-2:      #5B554A;   /* 灰墨（次要文字） */
--red-vermillion:#C63D2F;/* 朱批/印章（唯一强调&危险同色，用形状区分） */
--green-jade: #2F7C6C;   /* 青黛（成功/PASS） */
--gold-saffron:#B8860B;  /* 鎏金（进行中/待确认） */
--line:       #D8CFBB;   /* 界栏线（稿纸细线） */

/* 主题二：夜间「灯下稿」 */
--paper:      #1B1A17;   /* 墨底 */
--ink:        #EDE6D6;   /* 暖白字 */
--ink-2:      #A99E8B;
--line:       #3A362C;
--red:        #E06A58;
/* 一盏暖黄"台灯"径向渐变作页面氛围底 */
```
- **字体**：展示/标题用 **Noto Serif SC / 思源宋体**（回目感）；UI/正文用 **Noto Sans SC / 思源黑体**；批注、diff、字数等"账房数据"用 **JetBrains Mono + 中文 fallback**。**禁用 Inter/Roboto/system 默认**。
- **网格/背景**：内容区以 `repeating-linear-gradient` 做极淡稿纸横线（`line-height` 对齐正文行高）；编辑区下方为无横线的"白页"。
- **装饰元素**：书签标签（当前页顶部题签）、印章式状态徽标（红色方章=blocking，青黛方章=PASS，鎏金圆章=待确认）、装订线竖纹。

### 1.3 反模板硬规则
- 不用紫渐变、不用卡片投影堆叠；卡片用 1px `--line` 描边 + 极轻阴影（更像便签，而非"玻璃卡片"）。
- 大标题用衬线 + 序号（卷一 / 第X回 感），数字与计量用等宽对齐。
- 状态不用红绿灯圆点，用**印花徽记**（见上）保持叙事一致。

## 2. 信息架构与导航

```
┌─ App Shell（顶部题签栏 + 左侧书签导航 + 主区）─────────────┐
│  首页（书房） · 【当前项目】小说/拆文 … · 设置                 │
└──────────────────────────────────────────────────────┘
```

**路由（React Router）**
```
/login(可选令牌)                     # 单机可选访问令牌
/                                        # 项目书房（书架）
/projects/new                          # 新建项目向导
/projects/:project                      # 项目页（书签选择：小说/拆文）
/projects/:project/novels               # 小说书架
/projects/:project/novels/new           # 新建小说向导（需求录入）
/projects/:project/novels/:novel        # 小说工作台
  /settings|/outline|/chapters|/state   # 设定/大纲/正文/状态（四个模块）
  /pipeline                            # 流程看板（阶段 + 每步确认）
/projects/:project/teardowns            # 拆文库
/projects/:project/teardowns/:td/id     # 拆文工作台
/settings                               # 渠道/模型/偏好/预算
```

**导航分级**
- 全局左栏（窄书签）：书房 / 设置。
- 项目内二级标签（题签式）：**小说书架 · 拆文库 · 流程看板**。
- 小说工作台三级标签（卷页式）：**设定 · 大纲 · 正文 · 状态 · 流程**。
- 每步确认的确认条为**浮动批阅栏**（页面底部，像编辑手边的红笔）。

## 3. 页面线框（Wireframes）

### P0 项目书房（首页 `/`）
```
┌──────────────────────────────────────────────────────────┐
│ 题签栏:  oh·story 编辑部            [设置]                  │
├──────────────────────────────────────────────────────────┤
│  我的书房                                                     │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐        + 新建项目     │
│  │项目题签   │ │项目题签   │ │（空书架位）  │                     │
│  │《XX 长篇》│ │《XX 拆文》│ │            │                     │
│  │ 3 书 12拆│ │ ...      │ │            │                     │
│  └─────────┘ └─────────┘ └─────────┘                         │
│  最近动笔: 小说《...》第 21 章 · 3 小时前 · 待确认(1)            │
└──────────────────────────────────────────────────────────┘
```
- 每个项目是一枚**题签卡**：书名衬线大题 + 一行元数据（书数/拆文数/最近活跃） + 封面色块（项目主题色）。
- "最近动笔"区：把用户要接着做的（待确认阶段）直接顶到第一屏。

### P1 新建项目向导（`/projects/new`）
三步横向步骤条（题签式步骤）：
1. **项目类型**：`新建小说项目` / `小说拆文项目` / `导入已有小说`（复用 `story-import`）——单选大卡。
2. **基本信息**：项目名、目录（默认 `--root` 下按规则生成）、主题色/封面色块。
3. **确认**：生成初始目录结构预览（`{项目}/小说 · 拆文库` 树状预览），"落笔"按钮 → 建库 + 首次 `story-setup` 等效初始化（部署子代理模板/AGENTS.md/目录），自动进 `projects/:project/novels/new`（若选了新建小说）。

### P2 新建小说向导（需求录入，`/novels/new`）
这是"**用户需求 → 智能体**"的第一入口，表单化（不是聊天框）：
```
① 题材      [都市系统流 ▾ | 玄幻 | 女频……]（多选标签+权重）
② 类型      [长篇 ▾/短篇 ▾]  目标字数 ____
③ 平台/风格 [起点/番茄/晋江 ▾]  → 自动带出对应模板与去AI味档位
④ 一句话Idea（可选）____________________
⑤ 金手指/核心爽点（可选，多标签）……
[立即开始]（→ 生成项目骨架 + 进入 pipeline，从 concept 阶段起步）
```
- 右侧"模板参考"浮签：展示该题材/平台组合的 prose-card 摘要（来自知识库检索），帮助用户选型。
- 提交后走流程 `intake → concept → …`，向导即"第一步需求卡"。

### P3 小说工作台（四大模块 + 流程看板）
统一布局：**左侧结构树（书签式）+ 中央手稿区 + 右侧工具廊（AI 编辑 / 属性 / 门禁）**，通过 El 选项卡切四个模块。

```
┌─────────┬──────────────────────────────────┬───────────────┐
│ 结构树    │ 手稿区                             │ 工具廊          │
│ 设定▾     │ [========= 当前页标题 =========]     │ [工具标签]      │
│  题材定位  │  …正文/设定/章节卡片排版…              │  AI 编辑        │
│  世界观    │    （以"书页"样式呈现）                  │  ├选中→改需求    │
│  角色      │                                     │  │(diff对比/采纳) │
│ 大纲▾     │  […CodeMirror 或卡片列表…]            │  属性/引用       │
│  卷纲      │                                     │  门禁快报        │
│  细纲      │                                     │  └───────────── │
│ 正文▾     │                                     │                │
│  章节列表  │                                     │                │
│ 状态▾     │                                     │                │
└─────────┴──────────────────────────────────┴───────────────┘
```

#### 3.1 模块一：设定（可视 + 可改 + AI 编辑）
- **题材定位**：结构化字段卡（受众/平台/基调/核心卖点/一句话），字段行内编辑。
- **世界观**：多对"设定卡"（力量体系/地理/组织/规则），每卡含标题栏 + 正文；支持引用关系连线（`世界观:X§小节` 自动解析，悬停显示被引用处）。
- **角色**：**角色卡网格**，每张卡：头像槽（`story-image` 生成）、姓名、身份、目标、状态（从追踪状态实时回填）、开放线程（open_threads）计数 **红色朱批角标**。点开 = 角色详情页（大卡 + 语言风格档案 + 关系 + AI 编辑）。
- AI 编辑入口无处不在：卡片/字段右上角「✒ 由我改」按钮。

#### 3.2 模块二：大纲（层级可视化 + 章节卡）
- 左树：`卷 → 细纲章`（`大纲/卷纲/，大纲/细纲/`）。
- 手稿区：细纲 = **章回卡**，内含契约字段（结构公式/禁提前释放/情节点/人物关系出场/结尾钩子），字段行内编辑；缺失字段高亮 → 右上角朱批「字段缺失」。
- 顶层**大纲总览图**：卷/阶段色带（时间轴），点章进入该章卡。
- 章节间**钩子链可视化**：上一章结尾钩子 → 本章承接（连线小图）。

#### 3.3 模块三：正文（书页式编辑器）
- 左：章节目录（零填充编号 `第001章_标题`），当前章高亮，失败/Revision 标记。
- 中：**CodeMirror 6** 编辑（markdown 高亮、行号、软换行、中文输入友好），书页式（衬线正文、集中的版心、两侧留白如装订）。
- 行尾/左下：实时**字数**（与细纲目标对比），草稿存本地。
- 顶栏：`三查状态`徽章（查1/查2/查3 勾选）+ `保存并跑门禁` 主按钮 → 触发 `chapter` gates → 右下角浮签弹出门禁报告。
- **Revision 切换器**：正文多版本（`_rev`）可视切换，diff 对比。

#### 3.4 模块四：状态（追踪可视化看板——最重要的"可视化"）
数据面 `_tracking-state.json`（唯一权威），界面只读投影 + 由 Agent/用户编辑触发 `tracking-commit`：
- **进度区**：`last_committed_chapter / 目标章节` + 卷进度条；`next_chapter_commitments` 置顶为「下一章待办」浮签。
- **位置区**：`context.position`（场景/故事时间/卷）——一屏"此刻在哪"。
- **角色状态网格**：每个角色一卡（state / goal / open_threads / relationships / location），Open threads **朱批计数**；点击角色 → 跳到设定·角色卡。
- **伏笔看板（foreshadow）**：按 `planted_chapter → planned_resolution_chapter` 排成**时间线泳道**；`status` 用印徽（已埋=鎏金、已揭示=青黛、待收=朱）。距离应揭示章节 ≤2 章时浮签提醒。
- **时间线看板（timeline）**：事件 E### 按 story_time 排布，`reveal_status` 分读者已知/作者真相二态着色；未揭示事件淡显。
- **风险/红线**：`continuity_risks / long_term_constraints` 为**批注栏**样式，禁止一键修改，只能经修订流程。
- 右上「刷新」= 重读文件；「同步到流水线」= 下一次 stage 的 Context 组装以本页为准（其实自动，按钮仅为心理锚点）。

#### 3.5 流程看板（P4，每步确认落地页）
```
阶段:  intake ✓ → concept ✓ → characters ✓ → outline ⏳(review) → chapter → review → deslop → cover → export
       ┌────────────────────────────────────────────────────┐
       │ 当前阶段【outline·大纲】 revision 2       已用 ¥0.42   │
       │ 产物: 大纲/细纲/第001-020章.md  ...  [查看/编辑]       │
       │ 门禁: outline-detail ✓ · outline-copy ✓ · 结构公式 ✓ │
       │ ┌ 批阅栏 (底部浮动) ──────────────────┐              │
       │ │ [通过] [改后重跑] [驳回重写] [跳过]  │  附言____     │
       │ └───────────────────────────────┘              │
```
- 阶段轴卡片：`pending → running(流式进度) → review(待确认) → done`；blocking 阶段红印。
- 运行中：卡片显示 `Agent.subscribe` 桥接的 SSE 文字流（轻量"墨迹"更新）。
- 批阅栏即 §"每步确认"的交互：通过/改后重跑/驳回重写/跳过，均写 `audit`。

### P4 拆文工作台（`/teardowns/:id`）
```
① 原文导入: 粘贴/上传 → 分章（复用 story-long-analyze 抽取）→ 逐章摘要+情节点
② 拆解模块标签: 角色 | 设定 | 剧情模块 | 节奏 | 情绪曲线 | 爽点钩子 | 写作手法
   角色: 拆出角色卡（沿小说相同的卡样式，标注"实例"）
   剧情: 情节节点时间线 + 情绪模块卡
   节奏: 每章"慢/快"条带图（柱状节奏图）
   情绪曲线: 全本情绪走向折线（叙事可视化）
③ 拆文库沉淀: 一键「存为模块库」→ 供新小说"剧情模块化重组"复用
```
- 拆文全程只读分析 + 批注；AI 编辑可用于"写拆解报告"部分（写作手法/拆文报告）。

### P5 AI 编辑抽屉（"AI 根据需求编辑"的统一体验）
在设定/大纲/正文任意模块点击 ✒ 打开，或选中文本后唤出：
```
┌─ AI 编辑器（右侧抽屉，宽640）──────────────────────┐
│ 对象: 第003章_这个拍MV… · 选中范围 L120-145           │
│ [改写为更有爽感] [加伏笔] [压缩到800字] [自定义需求____] │
│ 参数: 角色模板(writer▾) 模型(pro▾) 语气(口语化/书面) 强度│
│ ───────────────────────────────────────────    │
│ 原稿(选中/整页)         │ AI 产物(diff: +绿 -朱)     │
│ ───────────────────────────────────────────    │
│ 需求上下文自动注入: 本章细纲·角色open_threads·文风档案   │
│            [应用] [放弃] [重写一次] (成本 ¥0.012)      │
└────────────────────────────────────────────────┘
```
- 机制：调 `POST /api/books/:id/ai-edit`，后端走 `Agent`（writer/architect 模板）生成 → diff 高亮 → **应用=落盘为 revision + 可立即触发门禁**。
- 与主流程关系：AI 编辑是**辅助小工具**，不占据流程阶段（符合"非聊天驱动"原则，仅创作自由区允许）。
- 需求模板按钮按模块定制（正文：加悬念/改开篇/缩字/改人称；设定：补强动机链/世界观圆场；大纲：加钩子/拆章）。

### P6 设置页
- 渠道管理（pi-ai `createProvider` 可视化）：名称/baseURL/API key(掩码)/模型目录（可 `refresh` 拉/增删）/连通性测试。
- 角色→模型路由表（writer=pro / checker=flash…）。
- 风格与预算：默认去AI味档位、每阶段 token/费用上限、生成图片品质。
- 保存位置提示：`webui-config.json`（密钥 0600）。

## 4. 关键交互流程（Flows）

### F1 新建小说 → 内容产出（主链路）
`书房[新建小说] → 需求向导(题材/字数/风格/金手指) → 骨架生成 → 流程看板 concept → 设定(角色/世界观/题材) → outline(细纲) → chapters(正文) → …`
每阶段在 **批阅栏** 等用户"落款"，未确认不进下一步（每步确认）。

### F2 AI 编辑（附需求 → 改稿 → 采纳）
```
选中文本/定位章节 → 点 ✒ → 选需求（或自定义） → 后端 Agent 生成
→ diff 浮签（绿增朱删） → [应用: 存 revision+门禁] / [放弃] / [重写一次]
```
- 应用后若 blocking 门禁未过：正文模块顶栏红印提示，不静默入正稿。

### F3 状态可视化联动
`状态模块 高亮 open_thread → 点击跳 设定·角色卡 → 该卡朱批角标闪烁一次`（跨模块 trace）。

### F4 每步确认与门禁
阶段产物 + 门禁报告 → 批阅栏四选一 → `audit` 留痕 → 状态机推进；blocking 时只允许"改后重跑/驳回"，不允许直接"通过"。

| `ToastSeal` | 浮签通知（批注气质，非普通 toast） | 全局 |
| `ChannelSettings` | 渠道/模型路由配置 | P6 |

## 6. 主题与质感细节

- **日间/夜间切换**（`灯下稿`）：一键点亮"台灯"，全局色板整体翻转（§1.2 tokens）。
- **首屏动效**：页面载入时，题签卡自上而下轻微"落版"（`animation-delay` 交错）；无 heavy 动画。
- **点头反馈**：确认/应用 = 一枚红色"章"盖下（scale 0.9→1.0 + 0.2s），比普通按钮有仪式感。
- **浮签**：右上滑入带书写感的批注条；blocking 浮签带红色印章边。
- **书页版心**：正文区 max-width ~720px 居中，行高 1.9，首行缩进两字（网文排版），两侧留白呼吸感。
- **无障碍**：对比度满足 WCAG AA（朱色#C63D2F 上白字在正文背景可用，必要时加深）；全部可键盘操作；CodeMirror 无障碍标注。
- **代码层面**：CSS 变量 + Tailwind 主题插件承载 tokens；Motion（Framer Motion）做 diff/抽屉/印章动效；icon 用自绘线性图标（笔、章、册、链），避免通用 emoji。

## 7. 前端状态管理

- **服务端状态**：TanStack Query（缓存 `GET /api/books/:id/*`，SSE 增量失效）。
- **SSE 接入**：`useSseJob(id)` hook 桥接 `GET /api/books/:id/jobs/events`（阶段进度/门禁批次/完成），事件写进 Query 缓存。
- **本地/草稿**：正文编辑用 CodeMirror 本地模型 + debounced 草稿到 localStorage；「保存并跑门禁」才走 `PUT /api/files`。
- **客户端路由**：React Router（`/projects/:project/novels/:novel/:module`，模块间保持左树展开态）。
- **编辑乐观锁**：`PUT /api/files` 带文件 mtime，冲突 → 批注栏提示"文件已被他人/进程改动"（延续 Dashboard 冲突保护）。

## 9. 效率与通知（面向日更作者）

### 9.1 键盘快捷键
| 快捷键 | 动作 |
|---|---|
| `Ctrl/Cmd+S` | 保存（并提示可跑门禁，不自动跑） |
| `Ctrl/Cmd+Shift+S` | 保存并跑门禁 |
| `Ctrl/Cmd+E` | 打开 AI 编辑（选中文本时以选区为目标） |
| `Ctrl/Cmd+Alt+R` | 流程看板：运行当前阶段 |
| `Ctrl/Cmd+Enter` | 批阅栏「通过」（focus 在批阅栏时） |
| `Alt+1..4` | 切换 设定/大纲/正文/状态 |
| `Ctrl/Cmd+P` | 当前书内快速跳转（章节/角色/伏笔） |
| `Ctrl/Cmd+Shift+K` | 打开追踪看板浮层 |
- 全站设置里可关闭/改绑（存储于 localStorage + `webui-config.prefs.keymap`）。

### 9.2 浏览器通知（任务结束/阻塞）
- 权限：`Notification.requestPermission()`（设置页开关，默认开）。
- 触发：`job:done`（阶段可确认）、`job:blocked`（门禁未过）、`gate blocking`、AI 编辑完成。
- 桌面场景下通知体带书名/阶段/小结；No-Do：不打扰进行中编辑（仅当标签不可见时弹）。
- 界面「设置→通知」：开关 / 仅阻塞 / 全部。

### 9.3 会话与多标签
- **服务重启恢复**：前端刷新后从 `GET /books/:id/stages` 重建；`running` 均已复位 `review`（ops §5），无"卡在运行中"假象。
- **多标签冲突**：同一文件双 tab 编辑 → 双方持 mtime，后者保存 409 → 提示 reload 或 diff 合并（MVP：提示 + 放弃后重载）。
- **书签角标**：左栏项目/书籍书签显示「待确认 N / 阻塞 M」小红章，跨标签 SSE 同步。

### 9.4 全局搜索
- `Ctrl/Cmd+P` 打开：搜章节标题/角色名/伏笔 ID/设定小节（后端 `GET /api/search?q=`，索引=文件名+标题+`_tracking-state.json` 摘要），结果按模块分组，回车跳转。
