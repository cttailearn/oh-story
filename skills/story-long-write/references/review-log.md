# 审查记录契约（review-log）

> 语义审查（写入审查 write-review / 大纲安全审查 / 七检）必须有**落盘产物**：审查记录文件。
> **「审查记录缺失 = Gate 未完成 = 不得报告完成」**——这是完成定义的一部分，不是可选项。
> 机械校验（脚本）与语义审查（记录）缺一不可：产出 ✓ + 机械校验 ✓ + 审查记录 ✓ 三元组齐备才算完成。

## 文件位置与命名

- 目录：`大纲/审查记录/`（自动创建）
- 命名：`{类型}.md`——`设定审查.md`（Gate A 后）、`大纲审查.md`（Gate B 后）、`细纲审查_第{batch}批.md`（Gate C 后，按批累计）、`正文审查_第{章}.md`（**每章必写**，见下方「正文审查」节）、`重排影响_YYYYMMDD.md`（重排后必写，见 workflow-revision.md）

## 固定模板（每份记录必含以下栏目，栏目缺失即视为未完成）

```markdown
# {类型}审查 — {日期}

- 审查范围：{本次写入的文件清单}
- 执行方式：{agent（consistency-checker）/ solo}

## 逐项检查（对应清单逐条，禁止"整体没问题"式概括）

- [ ] {检查项 1}：{判定 + 依据（引用的文件/行）}
- [ ] {检查项 2}：{判定 + 依据}

## 发现（S1-S4 分级）

- [S级别][类别] {描述}；出处：{文件}；处置：{已修/待用户确认/忽略及理由}

## 结论

- S1/S2：{已全部落实（列修改的文件）/ 未落实（阻塞，不得进入下一步）}
- S3/S4：{列出待确认项}
```

## 正文审查（每章必写）

> 正文审查记录由 `scripts/write-review-record.js` 按固定模板生成（`--data` 收三查结论 JSON；查1/查3 机械结果自动填入，查2 差异列表与 S1-S4 发现由模型提供；**查3 blocking>0 时脚本拒绝生成**）。

```markdown
# 正文审查 — 第{N}章 {章名}

- 查1 追踪状态（写前）：last_committed_chapter={N-1} / state_revision={值}；衔接 {正常/断档说明}
- 查2 细纲兑现（写后）：差异列表——{逐项：核心事件/情节点/禁止提前释放/复沓锚句/结尾设定，每项 ✓ 或 ✗ + 处理}
- 查3 禁用词 Gate（写后）：check-ai-patterns blocking={0/N}、check-degeneration blocking={0/N}；命中项 {已改/原因}

## 发现（S1-S4）

- {S 级发现逐条；无则写「- 无」}

## 结论

- 本章完成度：{可进入下一章 / 需补写（列项）}
```

## 重排影响（重排后必写）

重排（前移/后移/插删章）后按 workflow-revision.md Step 4 输出 `重排影响_YYYYMMDD.md`：受影响已写章节清单 → 正文硬事实回写结果（章序引用/日期/星期/倒计时）→ 追踪事务更新 → 正文 vs 新细纲冲突项。

## 修改清单（大修/重写前必写）

```markdown
# 修改清单 — 第{X}章 {章名} — {YYYYMMDD}

- 修改模式：{全文重写 / 局部修改}
- 用户修改要求：{动机/情节/语气/字数/节奏，逐条}

## 分段定位

| 段 | 原文定位（场景/段落号+首尾引用） | 改动意图 | 新内容要点 | 完成 |
|---|---|---|---|---|
| 1 | ... | ... | ... | □ |

## 联动影响清单

- [ ] 角色状态（追踪/角色状态/{名}.md）
- [ ] 时间线/日期/星期/倒计时
- [ ] 前文引用（"上一章/第X章"表述）
- [ ] 后文衔接（本章结尾 → 下一章开头）
- [ ] 细纲对应点（该章细纲硬要求）

## 不可变事实清单（全文重写模式必写）

- [ ] 事实 1：{已发生事件/状态/引用/伏笔/锚点/时间线，10-20 条}
```

## 修订核验（大修/重写后必写）

```markdown
# 修订核验 — 第{X}章 {章名} — {YYYYMMDD}

- 机械层：check-revision-duplicate {PASS/FAIL + 命中项}；check-chapter-consistency {PASS/FAIL}；禁用词 Gate blocking={0/N}
- 衔接核对（局部修改）：主语承接/因果链/时间线/状态连续 逐条 ✓/✗
- 事实保留核对（全文重写）：不可变事实清单逐项 ✓/✗（✗ = 丢事实，已补回）
- 要求兑现核对：修改要求逐项 ✓/✗（✗ = 部分落实，已补改）
- 细纲硬要求复核：{对照结果}

## 结论

- 修订完成度：{通过，可继续 / 未完成（列阻塞项）}
```
