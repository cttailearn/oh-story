# 写入审查（write-review）：角色卡 / 设定 / 大纲 / 细纲 写后主动审查

> 定位：**写后自检阶段**。每次写入或修改角色卡、设定、大纲、细纲后**立即执行**，
> 主动查冲突 / 矛盾 / 不合理 / 需要修改的地方，输出 S1-S4 分级报告并落实修改。
> 与「机械校验」（Gate A/B/C、check-outline-detail.js、tracking_commit.py check）是
> **两步关系：机械先行（字段/数值/引用存在性），语义随后（本协议，冲突与合理性）**。
> 与 story-review 的关系：本协议是**单文件增量级即时审查**（写什么审什么，范围小、
> 次数多）；story-review 是**全书级深度审查**（用户主动触发，范围全）。两者口径一致
> （S1-S4 分级与 findings schema 复用 story-review / consistency-checker）。

## 触发时机（写后必做，不静默跳过）

| 写入动作 | 审查范围 |
| --- | --- |
| 新建/修改角色卡 `设定/角色/{名}.md`（含「角色线」标题） | 该角色卡 + 相关设定 + 已有角色卡 |
| 新建/修改设定（`设定/世界观/`、`设定/势力/`、`设定/题材定位.md`、`设定/关系.md`） | 该设定文件 + 引用它的角色卡/大纲/细纲 |
| 新建/修改大纲（`大纲/大纲.md`、`大纲/卷纲/*.md`、全书体量与阶段总览） | 该大纲文件 + 角色线 + 设定 + 已锁定细纲 |
| 新建/修改细纲（`大纲/细纲/*.md`，每批落盘后） | 本批细纲 + 卷纲/大纲 + 角色线 + 追踪状态 |

> 每次审查前先跑机械校验：`node <story-long-write skill 目录>/scripts/check-project-consistency.js --project {项目根} --scope setup|outline|detail|review`（按写入类型选 scope），机械结果并入审查记录「逐项检查」。

- 修改已锁定内容（前 10 章细纲、已写卷纲区间）按锁定规则需用户确认，确认后同样执行本审查。
- 细纲后设定补全新建档的角色卡/势力/世界观卡，建档完成后立即执行对应行审查。

## 执行模式（与 story-review 一致的两级降级）

1. **agent 模式（优先）**：spawn `consistency-checker` 子代理（pi：`.pi/agents/consistency-checker.md` 已部署；
   dsh：`.dsh/story-agents/consistency-checker.md` 模板，subagent prompt 引用模板正文）。prompt 必须自包含：
   项目目录、本次写入的文件路径、写入内容要点、审查范围（上表对应行）、S1-S4 分级要求、只读约束。
2. **solo 模式（降级）**：agent 未部署 / spawn 失败 / 已在子代理内时，主会话按下方「审查清单」自查。
3. 报告统一用 story-review 的 findings 风格：每项 `[S级别][类别] 问题描述；出处；建议修改`，
   类别限定 consistency / factual / format / causal / rule_boundary。

## 审查清单（按写入类型）

### A. 角色卡写入后

1. **基础信息字段完整**（基础信息/形象与能力/说话方式/角色线/写作红线/本书专属 6 大标题，
   见 character-basics.md 第 1 节）：核心目标/动机/弱点不允许 [待补充]。
2. **卡内一致性**：形象与能力、写作红线、能力上限之间无自相矛盾（如红线禁止 X、能力却写明可 X）。
3. **跨卡冲突**：与已有角色卡无同名/同定位冲突；同一事件/关系在两张卡中表述一致
   （不一致 → S2，指出以哪张为准的建议）。
4. **与设定交叉**：能力上限 vs `设定/题材定位.md` 升级台阶——越级解锁/上限越界 → S2；
   角色归属势力 vs `设定/势力/` 卡硬事实表——冲突 → S1。
5. **角色线阶段**：`### 阶段 N：` 从 1 连续编号无跳号重复（机械规则，consistency-checker 第零步 5）；
   阶段蓝图与「形象与能力」分时期对齐；与卷纲「人物弧线」一致。
6. **写作红线**：红线/禁忌明确到可执行（"不要写 X"而非"注意分寸"），无与剧情功能冲突的死路。

### B. 设定（世界观/势力/题材定位）写入后

1. **硬事实表 key 唯一**：同一 key 不重复登记；与已有卡同 key 不同值 → S1（指出以哪张为准）。
2. **层级归属**：力量体系等级/势力层级/世界观规则与已有设定层级一致，无"上位规则 vs 下位行为"悖论
   （如规则禁止复活、普通术法却能复活核心角色且无例外/代价 → S1）。
3. **交叉引用**：题材定位升级台阶 ↔ 角色卡能力上限 ↔ 卷纲终局储备，三者一致；
   设定新增内容是否与已锁定细纲/正文事实冲突（如新增"此地无传送阵"但细纲用过 → S2）。
4. **边界与代价**：规则有适用条件/例外/代价（worldbuilding.md 模板要求）；"无代价的零成本资源路径"
   若存在会破坏核心冲突 → S3，标注待处理。
5. **未登记引用**：细纲「本章设定引用」点名的设定文件/小节存在（机械校验已查），此处复查
   内容语义匹配（引用与写出的内容一致）。

### C. 大纲（体量/卷纲/大纲.md）写入后

1. **与角色线对齐**：卷纲「人物弧线」↔ 角色卡「角色线」阶段蓝图（先有角色线再写弧线，
   不一致 → 先修角色卡再修卷纲）。
2. **阶段边界**：各卷「可释放 / 禁止提前释放」与全书阶段划分、终局储备（题材定位）一致；
   禁止提前释放的内容未被本卷卷纲/细纲提前写出 → S1。
3. **体量与节奏**：全书总章数/字数与各卷体量合计一致（Σ 卷 = 总）；阶段占比在参考范围
   （10-15%/50-60%/20-25%/5-10%）内或注明偏离理由。
4. **伏笔与钩子链**：卷纲「本卷伏笔」表与全书关键节点、阶段钩子链衔接（上一卷末尾钩子
   在本卷有承接）；无"埋了不收/收了没埋"的断线 → S3。
5. **对标结构坐标**：有主对标书时，1/4·中点·3/4 锚定关键情节存在（缺失 → S4，提示补）。

### D. 细纲（每批）写入后

1. **与卷纲/大纲对齐**：`核心事件`/`单元ID/位置`/`阶段位置` 与剧情单元卡、卷纲一致；
   单元 ID 指向的剧情单元存在；阶段位置与全书阶段划分一致。
2. **与角色线对齐**：「本章设定引用·角色线:{名}·阶段N」指向的阶段存在且 N 有效；
   细纲目标情绪/人物关系变化与角色线该阶段目标一致（不一致 → S2）。
3. **与追踪状态一致**：`本章禁止提前释放` 与 `追踪/伏笔.md` 待回收行一致（提前释放了
   仍在埋的伏笔 → S1）；主角状态与 `追踪/角色状态/` 快照衔接（断档 → S2）。
4. **批内互查**：同一批细纲无章名重复、无相邻章情绪趋同（都是高压/都是低压 → S3）；
   章尾钩子与下一章开头承接（写正文前复查即可，S4）。
5. **契约风险**：`契约风险` 行按大纲安全七检⑥⑦填写；契约破坏 必须修纲（见 workflow-setup
   「大纲安全审查」）。

## 输出与落实

- 每项发现：`[S级别][类别] 描述；出处：{文件}；建议：{具体改法}`。
- **S1/S2 必须落实**：修本次写入文件，或修被它暴露矛盾的对照文件，**二选一不并存**；
  修改后再跑一次对应机械校验（check-outline-detail.js / tracking_commit.py check）。
- **S3/S4 列出**：报告给用户，由用户决定是否修改；不静默丢弃。
- **审查结论必须落盘**为审查记录文件（契约见 [references/review-log.md](review-log.md)）：
  写入 `大纲/审查记录/{类型}.md`（固定模板：审查范围/执行方式/逐项检查/发现 S1-S4/结论），
  **审查记录缺失 = 该 Gate 未完成**，不得报告完成（一致性脚本 `check-project-consistency.js --scope review` 机械校验）。
- 会话内同时给出一行摘要：`WriteReview: {文件} → S1×N S2×N S3×N S4×N（已修/待确认）`。
- 若本次写入就是细纲后设定补全的新卡：建卡 → 本协议 A 行审查 → 通过后再引用。

## 与现有流程的接线

- Phase 2 设定完成后：Gate A（机械）→ 本协议 A/B 行（语义）→ 进 Phase 3。
- Phase 3 大纲完成后：Gate B（机械）→ 本协议 C 行（语义）→ 进细纲。
- 细纲每批落盘后：Gate C（机械：check-outline-detail THIN/LEAN + 引用 grep）→ 本协议 D 行（语义）→ 批末预算核对。
- 正文写作阶段（Phase 4/5）的正文一致性审查仍由 workflow-chapter / story-review 承担，本协议不覆盖正文。
